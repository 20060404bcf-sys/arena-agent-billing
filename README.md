# arena-agent-billing（油猴脚本 · 自动更新源）

Arena Agent 计费指纹与自动筛选 —— **单文件**油猴脚本（Tampermonkey / Violentmonkey）。
本仓库只托管**构建产物**与自动更新入口，源码在其开发工作区内维护。

## 安装 / 更新

```
https://raw.githubusercontent.com/20060404bcf-sys/arena-agent-billing/main/arena-agent-billing.user.js
```

- 第一次**点上面的链接装一次**（Tampermonkey 会弹出安装页），之后脚本头部自带的 `@updateURL` / `@downloadURL`
  会让它自动检查更新：`@version` 一递增就升级。也可以在 Tampermonkey 面板里手动「检查更新」。
- 装好后页面右上角面板的标题旁会显示一行 `v0.6.6` 形式的**运行版本标记**（截图时可直接作为版本绑定证据）。

## 0.6.6 相对上一版的行为变化

用户口径（2026-10-11）：「**一般来说，得到了计费，那就可以直接判断了。**」

- **判定条件 = 本轮自己消息的完整计价**：`/cost` 里本轮消息（按消息 id 归属，轮次开始时已记账的旧消息不算）
  四个价字段齐全、`basePriceUsd` 有值、输出价 > 0、`totalChargedUsd` 有值 ⇒ **直接进入识别**，
  不再要求先观测到 Arena 的 `turn-complete`。
- **迟到的中断信号不得撤销已经成立的完成**：同一轮里 `error`/`abort` 包、连接被服务端收尾导致的读流抛错、
  缓冲溢出，都不再把输出完成态抹掉（三条路径汇流到同一处共享守卫）。**真机反例（会话 `01a129a6`）**：
  先 `@STREAM_END … wait:billing`（正常完成），紧接着一条连接收尾把它抹回 `WAIT_OUTPUT`，
  而该状态当时既无计时器也无出路 ⇒ 永久卡死、识别永不发生、面板上永远看不到反推出的模型名。
- **等待不再是死路**：`WAIT_OUTPUT` 与 `WAIT_BILLING` 都按有界节奏继续轮询本轮计价，账单一到就判。
- **面板文案随口径更新**：等待阶段由「等待输出完成」改为「等待本轮输出与完整计价」/「等待本轮完整计价」。
- **R1 未变**：会话**没有费用证据**时一律**暂停、绝不归档**。
- **R2 未变**：页面出现 `thinking` ⇒ 立即中断并归档（判据是**页面 DOM**，不是流量）。
- **R3 未变**：面板「费用读数」在**折叠态**也显示费用速览。
- 回退点：常量 `AUTOMATION_THINKING_ALWAYS_ARCHIVE=false`（页面出现思考即中断+归档的行为由该开关统管）。

## 边界

- 脚本只在本地页面运行，**不上传**费用、正文或凭据；产物内**不含**任何 `localhost` / `127.0.0.1` 依赖，也不加载外部资源（构建期有单文件契约断言把关）。
- 识别结果只给**候选集合**与未约束状态，不声称模型身份已被证明。
- **未做（如实标注）**：0.6.6 的修复**尚未在真机跑过一轮**（0.6.5 的真机运行暴露了卡死，修复本身只有单测 + 变异复核）。
  哪一条中断路径触发的（abort 包 vs 读流抛错）在真机上**没有定论**：`performance` 只见一条 `/realtime/.../out` 连接；
  因此守卫放在三条路径的汇流处，而不是只堵一条。
- 本仓库为公开仓库；若需停止分发，删除本仓库或把该文件改为占位即可。
